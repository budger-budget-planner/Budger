I want to introduce a functionality that stretches the category’s budget, so instead of changing the category’s budget entirely, one month’s spendings of that category can be extended to: 

- whatever amount from other categories for the same month (I may not be spending full amount of one category, but need bigger budget for another one) 
- Maximum of 200% of the category budget transferring funds from next month’s budget of the category (I will spend 150% of the budget this month, but only 50% next month). Stretching this way is only allowed once in two months, meaning if a stretch was made across March and April is cannot be made across April and May. It can only be done across May and June. Sticking to this example if user stretched in March, then this particular option would be greyed out and unavailable in April. 

This has to be represented in: 

- home tab: every record that is being stretched receives an orange badge “Stretch”. Additionally, the monthly total budget for that month should be adjusted to include the sum of all stretched coming from the following month and receive an orange label underneath stating the total sum of stretched budgets that came from the same categories in the following month. So if I stretched category A by 250 zl across March and April, and cat B across March and April by 450 zl, and my budget is 6000 zl, in March it should show 6700 zl with orange label “stretched by + 700 zl from following month” and in April it should show 5300 zl with orange label stretched for - 700 zl from last month”. 
- Categories tab: A) if stretch is happening between two categories on the same month, both categories need to have an orange font labels saying “stretched by -X/+X” where X is an amount and currency (so example “stretched by - $100”, along with “stretched by + $100”); B) if stretch is happening on same category across two months, label should show “stretched by + $100” on stretched category, and following month there should be a hardcoded “stretched by - $100”) on that category. 
- Dashboard tab:  Donut chart parts should be adjusted accordingly: A) if stretch happens between two categories on the same month the budgets remains the same and the parts are being adjusted. If cat 1 budget is 1000 zl and cat B budget is 500 zl, the whole budget being 5000 zl, normally cat A would be 20% of the donut and cat be would be 10% of the donut. Now is cat A is stretched by 250 zl at the expense of cat B, then the budget remains 5000, cat A is stretched to 1250 zl, so 25% of the donut and cat be is stretched to 250 zl, so 5% of the donut. B) stretch is happening on the same category across 2 months. Just as the budget gets adjusted in home tab, in dashboard tab is should also get adjusted in the budget field with proper labels. Additionally, the donut chart should be adjusted not to represent 360 degrees and monthly total budget, but an adjusted monthly total budget. So if cat A is 750 and budget 1500 normally it would appear as 50%. Now let’s suppose user stretched it across March and April by 250. Now in March this category should be presented as 1000 (categories 750+ stretched 250 from following month) of 1750 (1500 + 250). Donut should present it as 57% of the donut and also adjust the size of other parts as well. In April, the same category should be presented as 500 (categories 750 - stretched 250 from last month) of 1250 (1500 - 250). In April the donut should present cat A as 40% of the donut. in May all goes back normal, so budget is back to what user set it to - here 1500, and cat A is back to what was set, so 750. This remains so, until stretched again. IMPORTANT! If any combination of these 2 will appear (user will stretch cat A from cat B budget AND cat c across two months) then 360 of the donut should represent the adjusted budget, not the regular, meaning that any instance of stretch of one category over 2 months makes the donut look at adjusted budget rather than regular one. Visually, donut parts that are stretched should have orange border, similar to the red border when a category budget is overflown. When a stretched category is overflown the orange boarder is bypassed by the red boarder. Descriptions still have both labels, overflown percantage shown in red and orange information about the amount stretched. 
- Household tab: the users part of the household donut chart should have an orange boarder if they stretched across the months, meaning their monthly total budget is adjusted. When the stretch happens over categories and monthly budget remains the same there is no need for indictation. For personal donut chart the same rules should apply as for dashboard donut. If category is stretched in any way it should have the orange boarder, if its budget is overflown it should have a red order (orange boarder is bypassed). For stretches applied over 2 categories 360 degrees of the donut represents normal budget. For stretches applied to one category over 2 months 360 degrees of the donut should represent the user’s adjusted monthly budget. If there is a combination of these stretches, then any instance of stretch over 2 months automatically requires donut to represent adjusted budget. 

Category can be stretched only across two categories, meaning there is no way to stretch it with other category this month, and the same category later. One stretch per transaction. This also means that when transaction was stretched across two months, it cannot be stretched again but now with other category. If cat A was stretched across March and April, is cannot be stretched with cat B in April - it stays stretched by that March transaction and cannot be stretched any other way.  

Ui should look the similarity to support a goal and be placed right below it. That means it’ll have a three way toggle with same options: No (default), Fully, Partially. 
With fully chosen two dropdown lists appear. First one is called “Which” and contains all the categories. If a category was assigned prior to setting this the chosen category appears as the first one by default. If category was not assigned, when the stretch is completed, record is set to category that they chose in step one.  Second one is called “from Which” and should also contain all the categories. Here the top-most by default should be the same as the one chosen in first drop down with the additional label (from next month). Then there should be other categories saved by the user. For fully option, there should be a rule that if the amount is greater that 50% of the category that user chooses in the first dropdown, then an information is displayed below the first dropdown that the stretch over 2 months is not available for this transaction as it is greater than 50% of the category’s budget. For these instances, the same category should not be displayed in the second dropdown. Additionally, if user chooses partially, the input box for the amount should appear. If the categories chosen are the same, so user is stretching across 2 months, there should be a warining displayed that user is allowed to input the maximum 50% of budgets category.
